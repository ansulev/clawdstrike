       - Frontmatter: `title: "Observe, Synthesize, Tighten"`, `order: 5`, `track: "policy-lab"`, `description: "The iterative workflow for developing production policies"`
       - **Content structure:**
         a. **Introduction** section: Real-world policies are never written in one pass. The observe-synth-tighten cycle is how security teams develop policies that are strict enough to catch threats but permissive enough to let agents work.
         b. **Phase 1: Observe** section:
            - Start with `permissive` ruleset in a staging environment
            - Monitor guard verdicts: what's being allowed? what patterns emerge?
            - Look for: which domains the agent calls, which files it accesses, which shell commands it runs
            - Embed `<PolicyEditor />` showing a permissive policy with `settings.verbose_logging: true`
         c. **Phase 2: Synthesize** section:
            - From observations, build a profile of normal behavior
            - Create an initial policy extending `default` with domain-specific allowlists
            - Key insight: start with what you KNOW is safe, block everything else
            - Show a code block with an example synthesized policy based on observed behavior
         d. **Phase 3: Tighten** section:
            - Deploy the synthesized policy, observe false positives
            - Adjust thresholds: lower `max_additions` if patches are typically small
            - Add exceptions: if a specific tool needs a specific path, add it to exceptions list
            - Enable advanced guards: once basics are stable, turn on `prompt_injection` and `jailbreak` detection
            - Embed `<PolicyEditor />` with a tightened version showing the progression
         e. **The Cycle Continues** section: Emphasize that policy development is ongoing. New tools, new threats, new use cases. The cycle repeats but each iteration narrows the attack surface.
         f. **Policy Development Checklist** section: Provide a numbered list:
            1. Start with an appropriate base ruleset
            2. Monitor agent behavior in staging
            3. Synthesize observed safe patterns into allowlists
            4. Tighten by reducing default_action to block
            5. Enable detection guards (prompt injection, jailbreak)
            6. Review and adjust based on false positive rate
